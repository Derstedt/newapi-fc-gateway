# New API FC Gateway v2 设计

本页保留 v2.0.0 独立网关的设计记录。v2.1.0 新增原生插件入口，见 [插件设计](PLUGIN_DESIGN.md) 和 [安装说明](PLUGIN.md)；原有网关继续作为可选部署。

## 目标

一个入口覆盖现有 New API 的模型和渠道；按配置从可用模型中生成 FC 别名，默认 `原名-fc`，同时支持自定义前缀、后缀。客户端用原 New API Key 调用。增加模型时只需修改选择规则，或由已有通配规则自动命中，不创建新的 New API 渠道。

## 架构决策

采用 Node.js 内置 HTTP/HTTPS 的前置网关，复用 v1 已验证的正文解码和协议转换核心。

纯 provider 插件依然受宿主渠道模型清单、分组和路由管理约束。让它回调当前 New API 会再次进入鉴权、路由及计费流程，并要求隔离回环。本版将模型别名和正文转换放在客户端与 New API 之间：同一模型生成请求只进入原 New API 一次。

不修改 New API 源码、数据库、模型价格或原渠道。网关由单个 Docker 服务运行，使用现有调用者的鉴权头；无管理 API 密钥、共享上游模型密钥、模型数据库、后台同步任务或跨用户模型缓存。

## 配置与模型发现

`config/config.json` 包含 `models`、`exclude`、`prefix`、`suffix`、`with_tools`。`models`/`exclude` 为精确名称或含 `*` 的模式。默认空选择；`["*"]` 表示全部选择。前后缀不能同时为空。

网关处理模型列表和聊天请求时读取配置文件。修改配置无需重建镜像。

`GET /v1/models` 携带当前调用者鉴权请求原 New API。保留原模型条目；为命中选择规则的模型追加别名。别名只支持 Chat Completions，额外端点提示不得误导客户端选择其他协议。

若生成的别名已经是上游的真实模型名，真实名称优先，冲突别名不发布。不根据 `-fc` 后缀盲目改名。列表生成和调用解析共享同一个映射函数。

## 请求路径

1. 原模型名：请求体原样转发，New API 继续按原规则调度。
2. 可能的 FC 别名：使用同一个调用者凭据读取当前模型列表，验证别名映射；把 model 恢复为原名称，再使用 v1 的正文工具策略。
3. 已选 FC 别名的响应：JSON/SSE 中的模型名回写为客户端请求的别名，正文工具还原为普通 content。
4. 明确禁用/指定工具、结构化输出等仍遵守 v1 旁路约定；别名可解析，工具注入保持旁路。
   已有业务工具时，客户端明确的 `tool_choice: "required"` 保留；缺省或 `auto` 使用 `with_tools` 配置。
5. 原名称的其他 `/v1/*` HTTP API 直接转发，不扩展 FC 到 Responses、Messages、图像、音频或 WebSocket。

通过固定 New API 上游发送请求，传入路径不能替换上游 host。上游 HTTP 错误保持状态和响应。流式处理保留背压，客户端断开时取消上游；不自动重试或续写。

## 代码边界

| 文件 | 责任 |
| --- | --- |
| `src/content-json.js` | v1 的单字段 JSON 增量正文解码 |
| `src/transform.js` | v1 请求注入、非流式/流式正文还原 |
| `src/aliases.js` | 配置归一化、模型匹配、列表投影及别名映射 |
| `src/sse.js` | HTTP 字节流中的 SSE 分帧、UTF-8 解码及事件还原 |
| `src/gateway.js` | 固定上游代理、模型列表、聊天改写和取消 |
| `src/server.js` | 环境变量、配置路径、进程启动 |
| `scripts/select-models.mjs` | 获取模型、显示编号、选择并写配置 |

无第三方运行时依赖。不保留 v1 插件安装器及构建器作为第二套部署入口，避免两套接入方式混在一起。

## 验收与 review

保留 v1 核心测试；新增真实本地 HTTP 上游模拟集成测试。验证用户凭据隔离、实时列表、原名/别名冲突、前后缀、普通请求字节透传、工具调用、SSE UTF-8 分片、背压/取消和配置更新。

第一轮独立 review 检查需求和架构；第二轮由非实现者检查协议与网络；修复后第三轮检查集成、部署和简洁性。review 记录具体发现、修复、复验，区分本地模拟验证和实际 New API/模型实测。

源码最终推送至用户 GitHub 新建私有仓库，并提供同一版本 ZIP。
