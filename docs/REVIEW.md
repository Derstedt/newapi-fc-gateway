# Review 与验证记录

版本：2.0.0  
日期：2026-11-27

## 第一轮：需求与架构

由独立审查者比较 provider 插件聚合与前置网关方案，确认本版采用前置网关：

- 一个入口获取原 New API 的模型目录，给选中模型生成别名，不逐模型新增渠道。
- 每次列表与生成都沿用调用者自己的凭据；模型路由、用量和计费仍由原 New API 处理。
- 原名称与别名并存，真实名称优先；精确选择和通配选择共用同一映射逻辑。
- 配置目录整体挂载，支持 CLI 原子替换文件后下一请求直接读取。
- 保留正文转换核心，移除旧插件安装器与构建器，只维护一套部署入口。

结论：架构满足本次统一网关需求。

## 第二轮：独立交叉代码审查

三位审查者分别检查自己未实现的模块，覆盖 HTTP/SSE、模型选择、正文与业务工具共存。审查发现及处理如下：

| 发现 | 影响 | 修正 |
| --- | --- | --- |
| CLI 在空模型列表时提前退出 | 无法用 `none` 清空已有通配规则 | 只有 `--list` 提前退出，空列表仍允许交互 |
| SSE 首帧带 UTF-8 BOM | 首帧可能未经正文转换直接返回 | 仅移除流开头的一个 BOM，正文中的同字符保留 |
| Content-Type 判断大小写敏感 | 合法的 `Text/Event-Stream` 被当成 JSON，无法及时输出 | MIME 判断先转为小写 |
| `with_tools: auto` 会覆盖客户端明确的 `required` | 降低调用方明确的工具选择要求 | 保留显式 `required`；缺省或 `auto` 才使用配置策略 |

这些修改均先通过回归用例观察失败，再进行最小修正。同步清理了旧插件的 Go 状态持久化注释，没有新增兼容层或配置开关。

## 第三轮：修复后的独立复验

由非修复者重新检查原问题、请求策略与文档约定：

- 空模型列表的 `none` 操作已能将 `models: ["*"]` 保存为 `[]`。
- 独立真实 HTTP 探针叠加 BOM 单字节分片与混合大小写 MIME，确认上游尚未结束时正文已送达，内部工具名不外露，正文中的 BOM 保留，随后正常结束。
- 配置读取、CLI 文件替换与 Compose 目录挂载一致。
- 客户端明确的 `required` 保留；`none` 和指定工具仍旁路正文注入。独立的 20 种策略组合验证通过，输入对象未被修改。
- 原业务工具、混合调用、多 choice、用量、reasoning、refusal、截断原因保持相应协议语义。
- 运行时代码只依赖 Node.js 标准库与本地模块，未加入数据库、缓存同步、自动重试或续写机制。

复验结论：当前 Chat Completions 范围内未发现阻塞交付的问题。

## 部署检查与验证范围

- Dockerfile、Compose、README 命令与源码入口逐项核对；README 的 Bash 命令通过语法检查，Compose 通过 YAML 解析。
- 源码及选择工具共 7 个 JavaScript 文件、595 行，包含空行与注释；无 npm 依赖，无构建步骤。
- 测试连接本地模拟 HTTP 上游，覆盖真实 socket 与流取消，不代表已连接用户的 New API 或付费模型供应商。
- 当前执行环境没有 Docker，未声称完成镜像构建或实际容器部署。README 提供在已有 New API 环境中的安装及验证命令。
- FC 转换用于 Chat Completions；原模型名的其他 `/v1/*` HTTP 接口直接转发，WebSocket 不在本版范围内。

正文通过 function call 生成后仍由普通 HTTP/SSE 传输。代码保证转换、增量还原及结束语义；具体模型的正文质量和断流表现需要用实际渠道比较。
